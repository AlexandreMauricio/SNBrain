# Login Links and Digest Tokens - Time Limited Authentication

**In one line:** two ways of logging a user in without them typing a password: a **time limited authentication (TLA) link**, generated by the instance and sent by email or SMS, valid once and for a short time; and the older **digest token**, where a company portal that already authenticated the user passes the user name plus a keyed hash of it.

From the Brazil docs. Both run through Multi-Provider SSO (later chapter). Policies that restrict them: [[Adaptive Authentication]]; second factor: [[Multi-Factor Authentication]]. Replay protection for digest tokens: the nonce section of [[Local Authentication - Login, Password Policy and Password Reset]].

## Time limited authentication

Plugin **Time Limited Authentication** (`com.snc.authenticate.time_limited_authentication`). Links can only be created by the instance itself. Intended for **low-privilege users**, and always **followed by MFA**.

**Time Limited Authentication Config > New**:

| Field | Meaning |
|---|---|
| **Name**, **Active** | |
| **One time use** | the link works once. Clear it to allow **Max login attempts** |
| **Expiry** | seconds (default 45 minutes) |
| **Failed Redirect**, **External logout redirect** | URLs after a failed login and after logout |
| **Single Sign-On Script** | the SSO script used |

Also: **Multi-Provider SSO > Administration > Properties** > *Enable multiple provider SSO*; adaptive authentication and MFA (with *MFA with SSO*) enabled.

Generating a link (server side, global scope; for example from a notification script or, to try it, Scripts - Background):

```js
var tla = new global.TimeLimitedAuthentication();
// returns a query string: nonce=...&glide_sso_id=...&user=...&source=...
var query = tla.generateNonce('<user sys_id>', '<TLA config sys_id>', '<optional source label>');
```

```text
https://<instance>.service-now.com/login_with_sso.do?uri=<URL-encoded target page>&<query string returned above>
```

The application that calls the API is responsible for building and sending the link.

The docs' pattern for a role of remote workers: a role filter criterion for the role; a post-authentication policy condition on it (so only those users may use the link); the role added to role-based MFA and to the step-up MFA policy; and the SMS factor policy offered to that role. The user clicks the link and is asked for the texted code.

## Digest token authentication

A portal behind the company's own single sign-on sends, as HTTP headers, URL parameters or cookies, the user identifier and a **digest**: the Base64 of an HMAC of that identifier with a shared secret. The instance recomputes the digest; if it matches and a user has that identifier, the user is logged in. A changed user name gives a different hash, so one user cannot pose as another. Hash methods: SHA1, MD5, **SHA-256 (recommended)**.

**Multi-Provider SSO > Identity Providers** > a digest record (roles `sso_config_admin`, `adaptive_auth_admin`, `user_admin`):

| Field | Meaning |
|---|---|
| **Name** | |
| **User** | the user table field matched against the incoming value |
| **HTTP header name** | name carrying the user identifier, for example `SM_USER` |
| **HTTP Digest header name** | name carrying the digest, for example `DE_USER` |
| **Secret Passphrase** | the shared key (32 or more characters) |
| **Failed SSO Redirect**, **External logout redirect** | |
| **Single Sign-on Script** | `MultiSSO_DigestedToken` |
| **Client Type** | optional (*Iframe Embedded*); add the field to the form if needed |

Setting the record as **default** replaces the system-wide digest settings. A specific record is addressed by its sys_id:

```text
https://<instance>.service-now.com/login_with_sso.do?glide_sso_id=<sys_id of the digest record>&SM_USER=<user name>&DE_USER=<digest>
```

Digest links do not expire by themselves; for expiring links the docs point to TLA. The portal-side samples (Java `Mac` with `HmacSHA256`, a C# method with `HMACSHA1` / `HMACMD5`) compute the HMAC of the user name with the shared key and Base64-encode it.
